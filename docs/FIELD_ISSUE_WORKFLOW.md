# طريقة تجربة الأخطاء وإصلاحها — محلياً، 2026-10-20

هذه طريقة عمل تستعمل تصوير الهاتف وأدوات التقييم الموجودة؛ ليست زر تسجيل
جديداً داخل التطبيق، ولا تدريباً تلقائياً أو رفع صور إلى GitHub.

## المطلوب منك عند مشاهدة خطأ

1. ابقَ ثابتاً، بلا مشي مغمض. لا تدخل درجاً أو طريق سيارات لاختبار التطبيق.
2. خذ screenshot تظهر المعاينة والصناديق والحالة، أو صورة للمشهد الحقيقي.
   أرفقها هنا وقل جملة واحدة، مثل: «هذا حائط ولم يتعرف عليه»، أو «فرشة مسطحة
   وقال عقبة»، مع وصف ما سمعته إن كان الخطأ صوتياً. لا يلزم إعطاء Cursor أوامر.
3. لا تصور أشخاصاً دون موافقتهم؛ راجع ما يظهر من غرفة/وجوه/شاشات. الصور لا
   تُنشر في المستودع العام. الفيديو اختياري للمراجعة البصرية، لكنه ليس replay
   مدعوماً حالياً في manifest الصور، ولا نقيس FPS من لقطة واحدة.

غياب STOP أو صمت التطبيق ليس إشارة أمان. UNKNOWN/HOLD بسبب غياب دليل مسار
ليس بالضرورة ادعاء وجود عقبة؛ نسجل الفرق بين «لم ير الحائط»، و«صنّف شيئاً
خطأ»، و«لم تتوفر أدلة كافية للسماح بالحركة».

## ما يفعله Codex وCursor بعدها

- نحفظ العينة بموافقة صاحبها في `test-data/private/` أو تقارير QA المحلية
  المستبعدة من Git. ننسخ القالب إلى `test-data/scene-manifest.tsv`؛ لا نملأ
  القالب المتتبع ببيانات خاصة. يراجع الإنسان التصنيف/وجود الأشخاص قبل التقييم.
- نربط scene_id بالإصدار، بصمة APK، الوقت، crop/rotation، المخاطر/القرار
  الحقيقي، وصف الصوت، وإعدادات النموذج. إذا كان الهاتف متصلاً ومفتوحاً، نستخدم
  `scripts/test/redmi-evidence-baseline.ps1` لفحص ثابت قصير عند الطلب، لا تسجيل
  كل استعمالك. اللقطة لا تثبت ارتفاع الحافة أو المسافة أو زمن التنبيه.
- نحدد الطبقة المعطلة: التصنيف، المحاذاة، قدم الإطار، ثقة/تغطية العمق، الصوت،
  الواجهة أو دورة التشغيل. مشكلة USB أو crop لا تُحل بتدريب نموذج آخر.
- نضيف اختبار إعادة إنتاج قبل الإصلاح. Cursor ينفذ مهمة محددة بملفات منفصلة؛
  Codex يراجع السبب والتعديل ويشغّل regression قبل قبول النسخة.
- نبحث الحلول الجاهزة والبيانات المناسبة للفشل المثبت. نستخدم أوزاناً مدربة
  أولاً، ونقارن على نفس الصور والإعدادات. لا نخلط هذه العينة في التدريب ثم
  نعلن النجاح عليها كتقييم مستقل؛ لا تدريب جديد إلا عند وجود سبب وبيانات كافية.
- فشل تسمية الجدار قد يحتاج segmentation؛ تمييز سجادة مسطحة من حافة يحتاج
  هندسة/عمقاً بمرجع قياس، لا تجاهل كل ما اسمه rug. الدرج والزجاج والحواف
  الساقطة بوابات مستقلة، لا تختفي بتحسن متوسط الدقة.

## قبول الإصلاح

- اختبار الحالة الأصلية يفشل قبل الإصلاح وينجح بعده، مع عدم كسر حالات مجاورة.
- العينات المفقودة/القديمة أو العمق غير المتاح تبقى UNKNOWN/HOLD؛ لا CLEAR أو
  turn من فراغ الكاشف، ولا نخفض احتياطات STOP لإخفاء إنذار مزعج.
- البوابة المحلية تختبر الكود وAPK؛ اختبار الهاتف يقيس السلوك الحقيقي على
  المشهد نفسه. سماع الصوت وTalkBack يحتاجان حضورك، ولا نستبدلهما بسطر log.
- نوثق المنفذ والمختبر والمؤجل وسبب التأجيل في WORK_QUEUE وPROGRESS وTEST_RESULTS.

أي رفع لعينة خاصة لخدمة AI أو مستودع أو إضافة GitHub Issue يحتاج موافقة
منفصلة على العينة والوجهة، حتى لو كان رفع الكود العام مصرحاً به.
