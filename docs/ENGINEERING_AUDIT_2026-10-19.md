# مراجعة الأساس الهندسي — TriGuide-AI، 2026-10-19

## الخلاصة والنطاق

المشروع قابل للبناء، وفيه فصل جيد لعدد من سياسات القرار والاختبارات، لكنه
ليس نظام مشي موثوقاً بعد. المشكلة الأساسية ما زالت نقص الدليل الهندسي على
المسار، لا نقص عدد أسماء الأشياء. نحتفظ بـ modular monolith وبالمحاكي الصغير؛
لا إعادة كتابة، لا تدريب جديد، ولا إضافة نموذج آخر في هذه الجولة.

هذه مراجعة للمسارات الحرجة والكاميرا والتخزين والتقييم والبناء والخصوصية،
وليست تدقيقاً مستقلاً لكل سطر، أو فحص ثغرات شاملاً، أو شهادة سلامة.
الشجرة كانت متسخة قبل البداية؛ التغييرات السابقة محفوظة. لا commit/push أو
نشر، ولا خدمة مدفوعة أو صلاحية Android جديدة أو رفع صور.

تحسينا الجولة: بوابة تحقق محلية قابلة للتكرار، وفصل الأدلة الخاصة عن Git/APK.
المرجع التنفيذي للنتائج هو تقرير `outputs/reports/quality-gate/<run>/summary.json`،
وليس مجرد وجود أمر أو عدد اختبارات في وثيقة قديمة.

## 1. المعمارية الحالية

مخطط منطقي محلي من الكود، وليس خدمات منفصلة أو تصميماً مستقبلياً:

```text
Android APK (:app)
├─ MainActivity → TriGuideRoot / AppServices
│  ├─ CameraXSource → MediaPipe / EfficientDet-Lite0
│  │  └─ SceneObservation → GuidanceSession / NavigationDecisionEngine
│  │     ├─ VoiceGuidanceGate → AndroidVoiceSpeaker (offline TTS)
│  │     └─ SimulatedTricycleController → :sim-core (virtual only)
│  ├─ VoiceSettingsStore → private SharedPreferences
│  └─ LocalGuidanceMemory + PersonConsentStore → private guidance-memory/
├─ Production floor adapter → diagnostic seam, UNMAPPED, no positive path authority
└─ Debug-only activities (DUMP protected)
   ├─ Shared CameraX → EfficientDet + MOSAIC → boxes / surface preview
   │  └─ Explicit Describe only; no mask-to-navigation edge
   ├─ Static model probe → separately supplied private image
   └─ ARCore capability check → support only, zero acquired depth frames

Desktop, outside APK
├─ research/evaluate_ade20k_segmenter.py → local public ADE20K evaluation
└─ scripts/test/verify-local.ps1 → tests / Lint / build / APK + privacy policy
```

دليل المصدر: `MainActivity.kt`، `ui/TriGuideRoot.kt`، `camera/CameraXSource.kt`،
`domain/NavigationDecisionEngine.kt`، `domain/GuidanceSession.kt`، `memory/`،
`src/debug/` و`src/release/`. الملفات داخل `android-app/app/src/` إلا المحاكي.
لا خادم Backend أو قاعدة سحابية أو API companion في مسار التشغيل الحالي.

## 2. نقاط القوة التي نحافظ عليها

- الكاميرا ثنائية الأبعاد لا تصدر CLEAR أو turn من غياب الصناديق؛ فصل صريح
  بين خريطة المحاكي المصطنعة والمشهد الحقيقي، مع اختبارات invariants.
- سياسات العمر/الترتيب/العينات المميزة والإيقاف لها وحدات اختبار نقية؛
  STOP والرجوع المتوقف لا يحتاجان انتظار قرار AI جديد.
- مصدر CameraX واحد مسؤول عن إغلاق ImageProxy؛ KEEP_ONLY_LATEST، ومهمة
  segmentation واحدة قيد التنفيذ في المختبر، لا قائمة إطارات متراكمة.
- النماذج التجريبية وARCore في debug؛ release لا يحتاج هذه التجارب.
- تقييم جاهز يعتمد أوزاناً مدربة: SHA-256 للإطار والقناع والنموذج، مجموعة
  مشتركة، مقاييس لكل صنف، وقياس منفصل لخطر تصنيف الدرج كأرضية.
- ذاكرة الأشخاص أسماء مؤكدة فقط؛ لا صور وجوه/embeddings أو تعرف هوية مزعوم.

## 4. تقييم الاختبارات

الموجود: JVM للقرار/الصوت/الحداثة/المحاكي وعرض المختبر، و10 اختبارات Python
للتقييم، واختبارات هاتف يدوية/أوامر QA موثقة. `testInstrumentationRunner`
معلن، لكن لا حزمة `src/androidTest` ولا workflow CI فعلي في المستودع.
سجلات TTS أو `speak=0` لا تثبت السماع أو النطق أو تجربة TalkBack.

الجديد: `scripts/test/verify-local.ps1`، بأمر واحد من جذر المشروع:

```powershell
.\scripts\test\verify-local.ps1
```

يشغّل اختبارات سياسة الأدلة، اختبارات Python للتقييم، فحص manifest المشاهد
كقالب فقط، يعيد تشغيل اختبارات JVM فعلياً، يبني debug/release، ويشغّل Lint
للنسختين. ثم يفحص APK النهائي، لا source manifest وحده:

- الصلاحيات قائمة محدودة؛ INTERNET أو RECORD_AUDIO غير المعتمدين يفشلان.
- لا assets غير معتمدة أو نموذج ناقص/متغير البصمة؛ لا صورة اختبار في APK.
- release بلا نماذج المختبر أو أنشطة التشخيص أو ARCore SDK داخل DEX.
- أنشطة debug التشخيصية الثلاثة محمية بـ DUMP.
- عدد JVM لا يقل عن baseline الحالي 339/10؛ الغائب/الفاشل/المتخطى لا يصبح PASS.
- بصمة مصدر تشمل الملفات المتسخة والجديدة، وبصمة APK/policy ونتائج فعلية
  وسجلات في مجلد جديد. تغير المصدر أثناء الفحص يفشل الجولة.

يتطلب PowerShell 7، Python 3.11+ بمتطلبات `research/requirements-eval.txt`،
JDK17 وAndroid build-tools 35.0.0. يستخدم البيئة المحلية الموجودة إن وُجدت؛
لا يثبت برامج أو يعدل PATH دائماً. `-Python` و`-JavaHome` و`-SdkRoot` متاحة.
الافتراضي Gradle offline؛ لإحضار اعتمادات مجانية عامة ناقصة فقط:
`-AllowDependencyDownload`. هذا لا يمنح التطبيق الإنترنت أو يرفع بياناته.
لا install أو ADB أو نسخ فوق APK محفوظ في outputs/apk.

استخدمنا فاحص Android الجاهز بدل كتابة محلل binary XML جديد، وفق
[توثيق AAPT2](https://developer.android.com/tools/aapt2).
Lint errors تمنع PASS، والتحذيرات تُحصى ولا تُخفى أو تُحوَّل إلى baseline صامت.
هذه بوابة هندسية محلية، وليست CI أو بوابة أمان للمشي. لا تعتمد شهادة Git HEAD
وحدها لأن الشجرة تحتوي تغييرات غير committed.

النتيجة النهائية: **PASS** في
`outputs/reports/quality-gate/20261019T083518346232Z/summary.json`.
339 app + 10 sim + 18 policy + 10 evaluation = **377 اختباراً آلياً**، دون
فشل/خطأ/تخطٍ. debug/release build وLint ناجحان؛ تحذيرات Lint باقية ومكشوفة
(40 debug، 30 release، ليست بالضرورة 70 مشكلة مختلفة). أُعيد تنفيذ اختبارات
JVM؛ بقية المهام قد تستخدم نتائج Gradle المحلية. الجولات السابقة محفوظة.

## 6. تقييم AI

عُثر فعلياً على 2000 صورة validation و2000 mask في ADE20K المحلية؛ تقارير
الثلاثة نماذج الكاملة موجودة وتربط hashes واختيار العينات والإعدادات.
لم نُعد تدريباً أو نُعد تشغيل 6000 inference في هذه الجولة؛ أُعيدت اختبارات
المقيّم فقط. تفاصيل النتائج السابقة في `docs/ADE20K_OFFLINE_EVALUATION_2026-10-19.md`.

المهم: MOSAIC argmax لا يعطي confidence؛ Top31 لا يحتوي درجاً. لا نحول متوسط
IoU أو لون floor إلى إثبات مشي. Python reference يضع padding أعلى/يسار، بينما
Android probe يستخدم canvas مركزي مع bilinear Android؛ خيار centered في Python
تقريب، وليس إثبات parity بكسل ببكسل. يجب مقارنة مرشحين بنفس المسار قبل إعلان
تفوق على الهاتف. لا benchmark ذهبي من صورة الغرفة الوحيدة، ولا نعدل thresholds
لتناسبها فقط. ملف `apk-policy.json` هو قائمة packaging pins وليس ترخيص أوزان
أو model registry متكاملاً أو شهادة ثقة.

## 7. تقييم قياس الأداء وقدرات الجهاز

تحقق حالي عبر USB: Redmi 22101316G / Android API34، تطبيق 0.9.22/35 وخدمة
ARCore 1.57.262640093. PackageManager يعلن كاميرات وautofocus وRAW capability
وجيروسكوب وتسارع وبوصلة وضوء. إعلان الخاصية لا يثبت جودة القياس، أو وجود ToF.
دعم AUTOMATIC/raw أُثبت في تجربة سابقة مذكورة في `docs/SURFACE_LAB_AND_DEPTH_2026-10-19.md`؛
لم نجمع depth frames جديدة هذه الجولة. لا منافسة ARCore/CameraX على الكاميرا.

PerformanceMonitor يفصل callbacks الكاميرا عن نتائج inference ويحفظ نافذة 30
latency؛ مختبر الرؤية bounded ويقيس callback-to-map وinvoke منفصلين. هذه قوة،
لكنها ليست زمن المستشعر إلى القرار إلى الصوت. قياسات PSS الوحيدة القصيرة لا
تثبت غياب تسرب، أو ميزانية حرارة/بطارية لعشرين دقيقة. لا نبدّل CPU/GPU/NNAPI
دون A/B ثابت على نفس الجهاز/المشهد. لا حاجة لشراء حساس قبل قياس Raw Depth.

## 10. أول مهمة تنفيذية وحالة التسليم
